docs: 第四次修正 —— 不是「有没有」，是「有几个」

补看 499 赞那条，发现「正在发生」是数量关系。

## 新样本

499 赞「别再浪费 token」（41 秒，收藏 514 / 点赞 499）：
5 个画面里只有 1 个（聊天界面）可能在动。数据落在中低档。

## 修正后的曲线

  5~6 个  →  1 万+
  1~2 个  →  500 左右
  0 个    →  几十到一百多

之前说「至少 1 张就能上千」，实际是「1 张大约 500」。
要到 1 万+，需要大部分画面都在动。

## 为什么是数量

抖音看完播率。5 个画面都在动 = 每一段都有「后面会怎样」的悬念，
看得完；0 个在动 = 3 秒内划走。

「正在发生」提供的是「接下来会怎样」的期待。期待越多，看得越久。

## 四次修正的完整轨迹

1. GitHub 页面越多越差 → 537 赞那条推翻
2. 有没有成果画面 → 1.8 万赞那条推翻
3. 有没有正在发生 → 499 赞那条推翻
4. 有几个正在发生 → 暂无

每次都因为新样本落在「符合/不符合」的边界上。

## 方法论反思

前三次的共同错误：拿少数样本硬切一个二分法。

正确做法：先看足够多样本，把「变量值」和「结果」列成表，再找关系。
那张表一眼能看出是数量关系，不需要先假设「有没有」。

**教训：先列表，再找规律。不要先假设规律，再找样本验证。**
