fix: 字幕横向安全区（缩放基数 900 → 640）

## 问题

第 35 轮把字幕从 47px 提到 60px，可用宽度 860 → 920。

但抖音右侧有约 200px 的 UI 带（头像、点赞、评论、分享）。
按「12 字宽 × 60px = 720px，居中后右边界 900」算，**已经侵入 UI 区 20px**。

## 新增 check-safe-area.py

前两版都试图从渲染帧上找白色像素的包围盒 —— 两次都失败：

  · 第一版把字幕上方的内容框进去了（量到字高 107px，但字号只有 60）
  · 第二版把画面 grain 噪点当成文字（阈值提到 210 还是误报 x=1079）

像素法在这个场景不可靠：画面里有截图、渐变、颗粒噪点。

## 改成算

字幕宽度可以直接算，不需要看画面：

  显示宽度 vw × 字号 size = 文字宽度
  右边界 = 540 + 宽/2

字号公式在模板里固定：size = min(cap, round(base / vw))
从 subs.json 读每条的 vw，算出右边界。稳定。

## 算出来的真问题

  ajin      最大字宽 14.5  → 右边界 945  侵入 65px
  xiaokai   最大字宽 13.0  → 右边界 904  侵入 24px
  weitu     最大字宽 12.9  → 右边界 902  侵入 22px
  ganhuoju  最大字宽 12.0  → 右边界 876  刚好

超长的几条没有内部标点可拆，比如：
  「GitHub 上已经有 133 个 star，」  14.5 字宽
（GitHub 一个英文词就占 3.36 字宽）

## 改法

base 900 → 640，cap 60 → 56：

  vw 8    → 56px  右边界 764  安全
  vw 10   → 56px  右边界 820  安全
  vw 12   → 53px  右边界 858  安全
  vw 14.5 → 44px  右边界 859  安全

顺带试过 670（余量只有 2~4px，太贴边，各平台 UI 宽度不完全一致），
确认 640 才留出 20px 以上余量。
