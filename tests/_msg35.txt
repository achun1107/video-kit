feat: 一条命令从仓库到发布包（tools/auto-make.py）

## 为什么

前面 27 轮造了一堆工具，但都是散的：
评分、抽内容、写文案、生成配音、渲染、混音、封面、发布文案、打包 ——
要手动跑七八条命令，顺序错了还会出问题。

这个脚本把它们串起来。

## 自动决策：按评分决定做几条

  评分 ≥ 7   做 4 条（四种风格都用上）
  评分 5-6   做 2 条（手账批注 + 产品发布页）
  评分 < 5   只做 1 条，并提示换选题

评分 7 以下的项目，文案自动用 problem 风格（问题切入），
因为低星项目讲"有个开源项目"没人看。

## 用法

  python tools/auto-make.py owner/repo
  python tools/auto-make.py owner/repo --styles all
  python tools/auto-make.py owner/repo --out D:/my-video --force

## 实测中踩的三个坑（都加了保护）

1. 中断留下半成品
   跑到第二条时工具调用中断，留下一个 6 秒的 raw.mp4。
   重跑时 engine/render.py 看到它存在就跳过渲染，
   结果 final.mp4 只有 6 秒，但脚本没报错，一路跑到打包。

   保护：渲染前删掉 raw.mp4/final.mp4；渲染后检查时长，
   和 34.8s 差超过 1 秒就停下。

2. 补跑时用了 audio.py 而不是 tts.py
   audio.py 只更新配音不更新字幕，结果字幕和配音对不上。
   **preflight 的 C 项拦住了**（7/17 条对不上）。

   保护：auto-make 里统一用 tts.py。

3. headline 太长
   content.json 的 headline 来自 GitHub description，
   xiaobai-kanban 的是 39 字（"中文 AI 编程助手入门教程：认识 Agent、
   表达需求、安装 CLI 与学习 Git 工作流"）。

   评分工具早就预警过（"一句话说清 0.5/2，121 字太长"），
   但 auto-make 没管。

   保护：生成后检查，超 25 字就停下提示改 content.json。
   不自动截断 —— 截断会切掉语义，得人判断哪个是卖点。
