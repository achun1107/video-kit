## 二、两个变量，不是1个

### 变量 A：成果画面数量 → 决定「能不能火」

| 成果画面 | 赞 |
|---|---|
| 6 张 | 1.1万 |
| 5 张 | 7089 |
| 1~2 张 | 1067 / 537 |
| 0 张 | 40 / 1 |

**干净的正相关。有 1 张就能上千，0 张就是几十。**

### 变量 B：收藏率 → 决定「平台推不推」

| 收藏率 | 赞 |
|---|---|
| 106~109% | 7089 ~ 1.1万 |
| 96~100% | 537 ~ 1067 |
| **42%** | **40** |
| 4%（广告） | 3240（靠投放，不是推荐） |
| 2600%（资源类） | **1** |

**收藏率 96% 以上都在 537 赞以上；掉到 42% 只剩 40 赞。**

## 三、两个例外，各有解释

### 例外 1：千问办公（3240 赞，收藏率 4%）

- **时长 119 秒**（是自然内容的 2~3 倍）
- **真人占一半画面**（不是小头像）
- 带 `#千问办公` 品牌标签
- 收藏率只有 4%

**这是投放广告，不靠推荐流量。** 排除出自然内容样本。

### 例外 2：AX 短剧（1 赞，收藏率 2600%）

收藏 26 条，点赞只有 1 个。

**资源类内容的典型特征**：值得存，但不值得赞。
（"83 个 skill 整理好了" —— 存下来慢慢看，但不会想给作者点赞）

**说明收藏率高不是万能的，还得有"值得赞的时刻"。**

## 四、修正后的判断模型

```
第一步  有没有成果画面？
        ├─ 0 张  →  几十赞，别做
        └─ ≥1 张 →  进入第二步

第二步  观众会不会"想赞"？
        ├─ 只有存的价值（资源汇总、工具清单）→ 收藏高、点赞低
        └─ 有"卧槽这个牛"的时刻             → 收藏高、点赞高
```

**「想赞」的时刻来自哪里：**

| 有 | 没有 |
|---|---|
| 一个效果"太好了，我也想要" | "这个我存起来以后看" |
| 前后对比的巨大落差 | 平铺直叙的功能罗列 |
| 超出预期的成品 | 意料之中的工具介绍 |

## 五、对我们最有用的两条

### 1. 成果画面是入场券，不是满分项

1 张成果画面 ≈ 500~1000 赞。这已经比 0 张的几十赞好 20 倍。

**所以第一步不是做到 1.1 万，是先做到"至少有 1 张"。**

### 2. 我们的四条片子：0 张

ajin / ganhuoju / xiaokai / weitu，画面全部是 GitHub 仓库页面的不同呈现。

**按模型第一步就出局。**

## 六、抽样说明

264 条作品里，逐帧看了 7 条（2.7%），覆盖 7 个点赞档位。

不是全量，但每个档位至少 1 条，结论在档位之间是单调的，
再增加样本不会改变方向。

**广告和资源类两种特殊类型已单独说明，不混入自然内容统计。**
