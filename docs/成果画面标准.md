抓取时间：2026-11-09
背景：上一轮结论是「GitHub 页面越多，数据越差」。看了中间档之后需要修正。

## 二、上一轮结论的问题

按「GitHub 页面数」排序，Ian 那张是 3/5，按道理应该比「省 Token」的 2/5 更差。

但 Ian 有 537 赞，省 Token 只有 40 赞。**不是单调的。**

差异在哪：**Ian 的最后一张是黑白线条插画，是那个 Skill 的产出物。**

省 Token 的最后一张是 3D 卡通人物 —— 那只是装饰，不是"省 Token"这个工具做出来的东西。

---

## 三、修正后的结论

**关键变量是「有没有至少一张、观众一眼看得懂的成果画面」。**

- GSAP：6 张成果 → 1.1万赞
- Taste：5 张成果 → 7089 赞
- Ian：**1 张成果**（其余是 GitHub 页面）→ 537 赞
- 省 Token：0 张成果 → 40 赞
- AX 短剧：0 张成果 → 1 赞

**只要有一张成果画面，数据就能进到"几百赞"这一档。一张都没有，就是几十赞甚至个位数。**

---

## 四、成果画面的判断标准

一句话：**观众看到会想「我也想要一个」。**

| 是成果 | 不是成果 |
|---|---|
| 做出一个丝滑的网页动画 | 设置界面截图 |
| 一张设计稿 / 落地页 | GitHub 文件列表 |
| 生成的插画 / 图片 | 3D 卡通装饰人物 |
| 旋转的 3D 模型 | 终端里的文字 |
| 跑起来的游戏画面 | "省了 80% Token" 的数字 |

**核心：成果画面里，"成品"在画面里是主角；工具界面里，"工具"是主角。**

## 六、如果必须用这个项目（AI 编程入门教程）

**唯一可行的改法：把"教程"变成"成果"。**

### 错误做法（现在这样）
讲这个教程有什么内容 → 观众看到 GitHub 页面 → 没兴趣

### 可行做法
1. **跟着教程做出来的第一个东西** —— 直接展示成品
2. **零基础 3 天做出来的网页** —— 前后对比图
3. **让 Agent 从零写一个能跑的东西** —— 录屏 + 成品

**核心：观众要看的是"学完能做出什么"，不是"教程讲了什么"。**

---

## 七、选题的硬标准（一条）

**能不能截出至少 1 张「观众会想我也想要」的画面？**

- 能 → 有戏
- 能截出 5 张以上 → 大概率爆
- 一张都截不出 → 别做

**这个标准可以在立项前 30 秒判断完，不需要做完整条视频。**
