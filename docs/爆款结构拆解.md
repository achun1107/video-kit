## 四、两条爆款的四个共同点

### 1. 真人头像固定左上角
圆形小窗，直径约占画面宽度 1/6。**脸清晰，不是环境照。**
作用不是"露脸讨好"，是**给内容一个"人"的背书**。

### 2. 标题栏固定右上角，全程不动
「Codex 细说 GSAP 复刻苹果官网UI」
「Codex 审美闭环 / 全覆盖审美优化需求」

**观众随时知道在讲什么**，划到一半进来也能立刻接上。

### 3. 每 6.8~8.5 秒换一个完全不同的画面
- 51 秒 / 6 个画面 = 8.5 秒/个
- 33.8 秒 / 5 个画面 = 6.8 秒/个

**关键：每个画面是"不同的成品"，不是同一张图的裁剪。**

### 4. 超大白色字幕是唯一的口播载体
没有第二套文字。没有"标签""要点卡片""手写批注"。

## 六、最扎心的发现

**「插图少了」根本不是"图的数量"问题，是"图有没有变化"问题。**

我们的 6 个卡片，画面节奏（5.8 秒/个）甚至比爆款（6.8~8.5 秒）更快。
但每张都是同一个 GitHub 页面的不同裁剪 —— **观众感知不到变化**。

**而这是选题决定的**：
133 星的小工具，没有 6 个不同的成品可以展示。
爆款讲的 GSAP Skill、Taste Skill 本身就能产出多种视觉作品。

---

## 七、能立刻做的（不改代码）

### 1. 加固定标题栏
画面右上角常驻一行小字，写清楚"这条在讲什么"。
观众从任意时间点划进来都能接上。

### 2. 加"收藏钩子"
收藏率是这类内容的命脉（爆款 106%）。
口播里加一句"建议收藏，以后用得上"——一句话的事，但数据显示这类内容
收藏是点赞的 1 倍以上，说明观众确实在存。

### 3. 换选题
这是根本。**要展示"多个成品"，项目本身得能产出多个成品。**

---

## 八、结论

**爆款不是"讲得好"，是"东西好"。**

GSAP Skill 能做出丝滑动画，Taste Skill 能提升设计质感——
它们有东西可展示，所以镜头一转就是一个成品。

133 星的小工具，镜头转十次还是那个 GitHub 页面。

**工作流能改的是形式和文案，改不了"有没有东西可看"。**
