## 三、为什么「正在发生」比「成果」更准

「成果」是**名词**（一个东西）。
「正在发生」是**动词**（一件事）。

观众刷抖音时的心理：
- 看到一个**东西** → "哦，有这么个东西" → 划走
- 看到一件**事在发生** → "他在干嘛？" → 停下来看

**"正在发生"制造的是好奇，好奇比"好看"更能留住人。**

这也解释了为什么：

| 现象 | 解释 |
|---|---|
| 录屏类内容容易爆 | 屏幕在动，永远有"正在发生" |
| 静态截图难爆 | 没有"正在发生" |
| 真人出镜有效 | 人在说话，是"正在发生" |
| 教程类要演示操作 | 操作 = 正在发生 |

## 四、GitHub 页面为什么是负分

GitHub 仓库页面是**信息密度最高、动态最少的画面**：

- 一整屏文件列表
- 密密麻麻的 commit 记录
- 静止不动

**对作者**：这些信息说明项目活跃、结构清晰。
**对观众**：一屏看不懂的东西 + 没有动作。

**双杀：既不好看，也不在动。**

---

## 五、修正后的判断标准

### 一句话

**画面里得有「正在发生的事」。**

### 自检三问

1. 这一帧里，**有东西在动吗**？（对话滚动 / 代码输入 / 动画播放 / 鼠标操作）
2. 如果暂停在这一帧，**观众能看出"在干嘛"吗**？
3. **换成一张静态截图，效果会掉多少**？（掉很多 = 有"正在发生"；掉不多 = 本来就是静态的）

### 分数对照

| 画面类型 | 分 |
|---|---|
| 录屏操作（正在用工具做事） | 高 |
| 动画/视频播放 | 高 |
| 对话窗口（一问一答在滚） | 高 |
| 代码正在被写 | 高 |
| 成品图（做完的东西，静止） | 中 |
| 软件界面（设置/列表，静止） | 低 |
| **GitHub 仓库页面** | **最低** |

**四条都是"静态展示"。**

我们做的运镜（Ken Burns）、窗口弹出、星标呼吸——**都是"画面在动"，不是"事情在发生"**。

**这两者不一样：**
- 画面在动（推拉摇移）：观众知道是视频，但仍然没有内容
- 事情在发生（代码在写）：观众想知道后面会怎样
