## 二、修正后的结论

**不是「有没有正在发生」，是「有几个」。**

```
5~6 个   →  1 万+
1~2 个   →  500 左右
0 个     →  几十到一百多
```

**这条曲线比"有没有"更贴合数据。**

之前说"至少 1 张就能上千"，现在看是"1 张大约 500"。
要到 1 万+，需要大部分画面都在动。

---

## 三、为什么是数量而不是有无

抖音的推荐机制看的是**完播率**和**互动率**。

- 5 个画面都在动 → 每一段都有"后面会怎样"的悬念 → 看得完 → 完播率高
- 1 个画面在动 → 只有那 8 秒有悬念 → 其余时间想划走 → 完播率低
- 0 个在动 → 从头到尾没有悬念 → 3 秒内划走

**"正在发生"提供的是"接下来会怎样"的期待。期待越多，看得越久。**

## 五、判断标准（更新）

### 数一数

把视频按 6~8 秒切段，逐段问：

> **这一段里，画面中有没有东西在"进行中"？**

- 鼠标在移动 / 正在输入文字 / 代码正在滚 / 对话正在进行 / 动画正在播 / 进度条在走
  → **算 1 个**

- 一张静止的图 / 一张截图 / 一个已经完成的页面 / 一段静态文字
  → **算 0 个**

### 对照

| 数量 | 预期数据 |
|---|---|
| 5~6 个 | 1 万+ |
| 3~4 个 | 2000~5000 |
| 1~2 个 | 300~800 |
| 0 个 | 几十 |

## 七、这次的方法论反思

前三次修正的共同错误：**拿少数样本硬切一个二分法**。

正确做法应该是：**先看足够多的样本，把"变量值"和"结果"列成表，再找关系。**

比如这次：

| 视频 | 正在发生数 | 赞 |
|---|---|---|
| ChatGPT 直达 PS | 5 | 18000 |
| Codex 电脑全自动 | 4 | 16000 |
| Codex GSAP | 5 | 11000 |
| Codex 网页 Skill | 5 | 11000 |
| AI 全能前端 | 5 | 11000 |
| Ian 插画 | 1 | 537 |
| Token 消耗大减 | 1 | 499 |
| 70 行核心代码 | 0 | 199 |
| 多模型省 Token | 0 | 40 |
| AX 短剧 | 0 | 1 |

**这张表一眼能看出是数量关系，不需要先假设"有没有"。**

**教训：先列表，再找规律。不要先假设规律，再找样本验证。**
